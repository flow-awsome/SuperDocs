# mastery — 최초 인터뷰 & 셋업 툴킷

이 폴더는 **다운로드해서 새 프로젝트를 시작할 때 한 번 쓰는** 인터뷰 도구다. 실제 개발 중에 매일 참조하는 운영 문서 하네스는 여기가 아니라 [../docs](../docs/README.md)에 있다.

## 두 폴더의 관계

```
mastery/  (입력 — 한 번 채운다)
   │
   │  인터뷰 답변을 기반으로 docs/ 구성을 결정
   ▼
docs/    (출력 — 프로젝트 내내 실제로 쓰는 하네스)
```

- `mastery/`는 **질문지**다. 프로젝트의 정체성, 기술 스택, 이해관계자, 성공 기준, 문서 운영 방식 선호도를 묻는다.
- `docs/`는 그 답변을 바탕으로 실제로 채워 넣고 프로젝트 기간 내내 갱신해 나가는 **살아있는 하네스**다.
- 이 둘을 분리한 이유: 설정 질문과 실제 운영 문서가 한 곳에 섞이면, 프로젝트가 진행될수록 "이게 초기 설정값이야 지금 상태야?"를 구분하기 어려워진다.

## 사용 순서

1. [00-initial-intake](00-initial-intake/README.md)의 4개 문서를 순서대로 채운다 (서비스 정체성 → 기술 스택 → 이해관계자 → 성공 기준/리스크).
2. [01-docs-blueprint](01-docs-blueprint/README.md)에서 답변을 근거로 이번 프로젝트에 맞는 `docs/` 구성(감사 렌즈 수, 문서 크기 예산, 위험도 임계값 등)을 결정하고 `master-docs-setup-plan.md`를 완성한다.
3. 완성된 계획대로 `../docs/AGENTS.md`와 `../docs/00-control-tower/`를 채운 뒤, 실제 개발은 `../docs/`를 기준으로 진행한다.
4. 인터뷰가 끝난 뒤에도 이 폴더는 지우지 않는다 — 프로젝트 성격이 크게 바뀌면(피벗, 대규모 리스코프) 다시 돌아와 갱신한다.

## 이 폴더도 절대 규칙은 아니다

여기 질문지가 프로젝트 성격과 안 맞으면 비판적으로 수정하거나 생략해도 된다. 다만 생략한 이유는 [01-docs-blueprint/master-docs-setup-plan.md](01-docs-blueprint/README.md)에 남겨, 나중에 "왜 이 질문에 답이 없는지" 헷갈리지 않게 한다.
