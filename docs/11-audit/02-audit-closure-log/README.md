# 02-audit-closure-log — 감사 종결 추적

발견된 문제가 "고쳤다고 주장된 시점"과 "다음 감사에서 실제로 재검증되어 닫힌 시점"을 분리해서 추적한다. 이 분리가 없으면 "고쳤다고 기록됐지만 아무도 다시 확인 안 한 문제"가 조용히 방치된다.

## 템플릿

[_template-closure-verification.md](_template-closure-verification.md)

## 상태 값

| 상태 | 의미 |
|---|---|
| 발견됨 | 감사에서 최초 발견 |
| 패치완료 (미검증) | 수정했다고 보고됐으나 다음 감사에서 아직 재확인 전 |
| 재검증완료 | 다음 감사 라운드에서 실제로 해소됨을 확인 |
| 재발 | 패치했다고 봤으나 다음 감사에서 다시 발견됨 — 근본 원인 재분석 필요 |

## 작성 원칙

- 각 발견 사항은 완전히 "재검증완료"가 될 때까지 이 로그에서 추적한다.
- "재발" 상태가 된 항목은 단순 재패치로 끝내지 않고 [07-decisions](../../07-decisions/README.md)에 근본 원인 분석을 남긴다 (같은 문제가 계속 재발한다는 것은 구조적 원인이 있다는 신호).
- **"패치완료 (미검증)" 상태가 다음 정기 감사 예정일을 넘겨도 그대로면**, 방치하지 않고 [00-control-tower/open-questions.md](../../00-control-tower/open-questions.md)에 "다음 감사 라운드를 언제 열 것인가"를 묻는 질문으로 등록한다. 1인/AI 단독 운영에서는 다음 라운드를 스스로 잊고 넘어가기 쉬운 지점이다.
