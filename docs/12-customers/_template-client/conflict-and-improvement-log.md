# 충돌 및 개선 로그: (고객코드)

baseline([../../01-architecture](../../01-architecture/README.md), [../../02-scenario](../../02-scenario/README.md))과 이 고객사 요구사항이 충돌하는 지점을 추적한다.

이 문서는 [06-history](../../06-history/README.md)와 달리 **append-only가 아니다** — 같은 항목이 시간에 따라 상태를 바꿔가며 살아있는 표로 관리된다. 실제로 처음엔 "충돌"로 보였던 것이 코드/STATUS 재대조 결과 이미 해소돼 있었던 것으로 판정이 뒤집히는 경우가 흔하다 — 그 판정 변경 과정 자체가 다음에 같은 오판을 반복하지 않게 해주는 기록이다.

## 상태 값

| 상태 | 의미 |
|---|---|
| 대기 | 충돌 후보로 접수됨, 아직 검토 전 |
| 제안됨 | 처리 방향(예외 처리 / baseline 개선)을 제안했으나 확정 전 |
| 반영 | 처리 결과가 실제로 코드/문서에 반영됨 |
| 보류 | 처리하기로 했으나 외부 의존/우선순위 문제로 미착수 — 재개 조건 명시 필수 |
| 해소 | 재확인 결과 애초에 충돌이 아니었거나(오판정), 반영이 완료되어 더 볼 필요 없음 |

## 항목 형식

```
### N. (충돌 제목)
- 상태: 대기 / 제안됨 / 반영 / 보류 / 해소
- 접수일: (YYYY-MM-DD)
- 고객 요구:
- baseline 현재 동작: (실제 코드/문서를 대조한 근거 — 추측 금지)
- 검토 과정: (처음 판단이 왜 바뀌었는지, 무엇을 다시 대조해서 확정했는지 — 이 부분이 나중에 같은 오판을 막는 핵심)
- 처리 결과: 이 고객만의 예외로 처리 / baseline 자체를 개선 (ADR 링크) / 오판정으로 해소
- 재개 조건 (보류인 경우만):
- 관련 문서:
```
