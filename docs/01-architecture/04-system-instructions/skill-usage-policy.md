# 스킬 사용 정책 (토큰 최적화)

에이전트가 사용 가능한 압축/탐색 스킬을 언제 어떻게 쓰는지 정한다. 목적은 하나 — **같은 결과에 도달하는데 드는 토큰을 줄이는 것**. 단, 정확성/명확성을 희생하면서까지 압축하지 않는다.

## 1. 압축 통신 모드 (caveman류)

- **언제 켜는가**: 반복적인 상태 보고, 단순 파일 탐색/수정 위주의 작업, 사용자가 이미 맥락을 충분히 파악하고 있는 후속 작업.
- **언제 끄는가(정상 모드로)**: 보안 경고, 되돌릴 수 없는 작업(삭제/강제푸시 등)의 확인, 다단계 절차라 문장 순서/접속사가 오독을 부를 수 있는 설명, 사용자가 명시적으로 요청할 때.
- **문서에는 적용하지 않는다.** 커밋 메시지, PR 설명, 이 하네스의 모든 md 파일(README, 결정기록, 히스토리 등)은 압축 모드와 무관하게 항상 정상적인 문장으로 작성한다 — 문서는 미래의 다른 사람/AI 세션이 읽을 영구 자료이기 때문이다.

## 2. 탐색 전용 서브에이전트 (ponytail/Explore류)

- **언제 쓰는가**: "이 코드 어디 있는지 찾아줘", "이 심볼 어디서 쓰이는지" 같은 순수 탐색 작업으로, 탐색 과정의 원본 로그가 메인 대화 컨텍스트에 남을 필요가 없을 때.
- **언제 안 쓰는가**: 이미 파일 경로/심볼을 알고 있을 때, 코드 리뷰나 설계 감사처럼 전체 맥락을 유지한 채 판단이 필요한 작업, 후속 편집이 바로 이어질 작업(왕복 비용이 더 클 때).
- 탐색 결과는 요약해서 메인 컨텍스트로 가져오고, 원본 탐색 과정(grep 결과 전체 등)은 가져오지 않는다.

## 3. 포크형 서브에이전트 (fork)

- **언제 쓰는가**: 현재 세션의 전체 맥락은 필요하지만, 그 작업의 중간 산출물(긴 로그, 반복 실행 결과)을 메인 컨텍스트에 남기고 싶지 않을 때. 독립적으로 답할 수 있는 여러 질문은 병렬로 포크한다.
- **언제 안 쓰는가**: 사용자가 포크 결과를 기다리며 바로 다음 대화를 이어가야 하는 짧은 작업. 사소한 1~2개 파일 수정.

## 4. 판단 기준 요약

새 스킬/에이전트를 쓸지 말지는 다음 질문으로 판단한다:

1. 이 작업의 중간 산출물을 내가 다시 볼 필요가 있는가? → 있으면 fork/서브에이전트 쓰지 않거나, 결과만 받는 방식을 쓴다.
2. 압축이 이 상황에서 오독 위험을 만드는가? → 그렇다면 압축하지 않는다.
3. 이 스킬을 쓰는 것 자체가 목적 도달을 늦추는가(왕복 비용 > 절감 토큰)? → 그렇다면 직접 처리한다.
