# 04-code — 코드

코드 내부 구조와 흐름을 **시나리오에 맞게** 비즈니스 로직 단위로 정리하는 공간이다. [01-architecture](../01-architecture/README.md)가 개념적 구조라면, 여기는 실제 코드 위치와 함수/모듈 단위의 구체적 흐름이다.

## 하위 구조

| 폴더 | 내용 |
|---|---|
| [00-module-map](00-module-map/README.md) | 실제 코드 저장소의 디렉토리/모듈 지도 |
| [01-business-logic](01-business-logic/README.md) | 시나리오별 비즈니스 로직이 어느 파일/함수에 구현되어 있는지 |
| [02-api-contracts](02-api-contracts/README.md) | 서비스 간, 프론트-백엔드 간 API 계약 |

## 이 폴더가 존재하는 이유

AI가 "이 기능이 어디에 구현되어 있는가"를 매번 전체 코드베이스를 탐색해서 찾지 않고, 이 지도를 먼저 참조해 빠르게 진입하게 한다 (토큰 절약). 단, 이 폴더는 **참고 지도**일 뿐 실제 코드가 항상 진실이다 — 어긋나면 코드를 기준으로 이 폴더를 갱신한다.

## 갱신 시점

- 새 모듈/서비스 추가 시
- 비즈니스 로직이 이동/리팩터링될 때
- API 계약이 변경될 때 (Breaking Change는 반드시 [07-decisions](../07-decisions/README.md)에도 근거를 남긴다)
