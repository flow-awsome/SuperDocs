# 02-integration-verification — 통합 검증

모듈 간, 실제 DB/캐시와의 연동을 포함한 검증. 백엔드 서비스 간 통신 검증도 포함한다.

## 검증 범위

| 범위 | 방법 |
|---|---|
| DB 연동 | 테스트 전용 DB 컨테이너 (Docker) |
| 캐시 연동 | 테스트 전용 캐시 컨테이너 |
| 서비스 간 API 호출 | 계약 기반 테스트 ([04-code/02-api-contracts](../../04-code/02-api-contracts/README.md) 기준) |

## 작성 원칙

- 통합 테스트는 단위 테스트보다 느리므로 핵심 흐름 위주로 선별한다.
- 서비스 간 계약이 깨지는 것을 잡아내는 것이 최우선 목적이다.
- **테넌트 격리/권한 경계처럼 한 번이라도 실제로 뚫렸던 지점**은 [regression-recheck-checklist.md](regression-recheck-checklist.md)에 등록하고, 이후 관련 변경마다 재실행한다 — 이 문서와 별도로 관리하는 이유는 "새 기능 검증"과 "과거 사고 재발 방지"가 성격이 다른 검증이기 때문이다.
- RLS/테넌트 격리처럼 Lv8-9급 검증은 모킹으로 대체하지 않는다 — 실제 DB/컨테이너로 실행한 증거(테스트 로그, 실행 일자)를 남긴다. "실행했다고 서술만 하고 실제로 돌리지 않은 검증"은 검증으로 간주하지 않는다.
